## 1. Теоретическая база

**Трекинг объекта** - определение положения целевого объекта в последовательности кадров. В данной работе используется поиск плоского объекта по его ключевым точкам: первый кадр (либо выделенная на нём область) принимается за эталон, после чего объект ищется на каждом кадре независимо. Для решения применены SIFT, FLANN, ratio-тест Лоу, RANSAC и гомография.

### 1.1. Обнаружение ключевых точек: SIFT

**SIFT (Scale-Invariant Feature Transform)** находит характерные локальные участки изображения и описывает их так, чтобы их можно было сопоставлять при изменении масштаба и повороте. Кандидаты в ключевые точки определяются через экстремумы разностей гауссово-размытых изображений (Difference of Gaussians, DoG) в пространстве масштабов. Затем уточняется положение точек, отбрасываются нестабильные отклики и назначается доминирующая ориентация.

Для каждой ключевой точки формируется **128-мерный дескриптор** - числовое описание распределения направлений градиента в её окрестности. В программе используются `cv2.SIFT_create(nfeatures=3000)` и `detectAndCompute()`. Эталонные ключевые точки и дескрипторы вычисляются один раз; для текущего кадра заново.

### 1.2. Сопоставление дескрипторов: FLANN

**FLANN (Fast Library for Approximate Nearest Neighbors)** позволяет относительно быстро искать близкие дескрипторы в многомерном пространстве. Для SIFT в работе настроен поиск с использованием KD-деревьев: `algorithm=1`, `trees=5`, `checks=50`.

Вызов `knnMatch(..., k=2)` возвращает для дескриптора эталона два ближайших кандидата на текущем кадре. Близость SIFT-дескрипторов оценивается по евклидову расстоянию: чем расстояние меньше, тем более похожи локальные признаки.

### 1.3. Отбор соответствий: ratio-тест Лоу

Ближайший найденный дескриптор не обязательно соответствует правильной точке. Для устранения неоднозначных совпадений применяется условие:

$$
d_1 < 0{,}75\,d_2
$$

где `d₁` - расстояние до ближайшего, а `d₂` - до второго ближайшего дескриптора. Если оба кандидата почти одинаково похожи, совпадение отбрасывается. В программе для продолжения обработки необходимо не менее **15 хороших соответствий** (`min_matches=15`).

### 1.4. Гомография и RANSAC

Для плоского объекта изменение положения, масштаба, поворота и перспективы можно приблизительно описать **гомографией** - проективным преобразованием с матрицей `H` размера 3×3:

$$
\begin{bmatrix}x'\\y'\\1\end{bmatrix}
\sim H\begin{bmatrix}x\\y\\1\end{bmatrix}
$$

Знак `~` означает равенство с точностью до ненулевого множителя: после преобразования однородные координаты нормируются.

Часть соответствий SIFT может быть ошибочной. **RANSAC (Random Sample Consensus)** многократно строит модель по подмножествам соответствий и выбирает преобразование, которое согласуется с наибольшим количеством точек. Точки, согласующиеся с найденной моделью в пределах порога ошибки перепроекции, называются **инлаерами**. В коде используется `cv2.findHomography(..., cv2.RANSAC, 5.0)`; принимаются решения минимум с **12 инлаерами**.

### 1.5. Построение рамки объекта

После оценки гомографии четыре угла эталонного изображения преобразуются через `cv2.perspectiveTransform()`. Полученный четырёхугольник отображается на кадре зелёной линией с подписью и числом инлаеров. В отличие от обычного ось-выровненного прямоугольника, такая рамка может учитывать наклон и перспективные искажения объекта.

Дополнительно проверяется выпуклость четырёхугольника и его площадь: рамка отбрасывается, если она вырожденная или не проходит заданные ограничения (`is_plausible()`). Если объект не найден, выводится `NOT FOUND`.

### 1.6. Ограничения метода

- На однотонных и сильно размытых поверхностях сложно выделить достаточное число устойчивых ключевых точек.
- Сильные блики, перекрытия, изменение ракурса и выход объекта за границы кадра могут уменьшать число корректных соответствий.
- Рамка зависит от правильности гомографии; проверки количества инлаеров, выпуклости и площади не гарантируют идеально точную локализацию.
- Алгоритм заново ищет эталон на каждом кадре, а не переносит координаты точек оптическим потоком. Это позволяет повторно обнаруживать объект после временной потери, но требует дополнительных вычислений.

## 2. Описание разработанной системы (алгоритмы, принципы работы, архитектура)

Программа реализована на **Python** с использованием библиотек **OpenCV** и **NumPy**. Исходный код находится в файле [`tracker.py`](tracker.py). Эталоном служит первый кадр целиком либо выбранная на нём прямоугольная область (`--roi` или `--select-roi`).

### 2.1. Инициализация

В функции `main()` открывается видео, читается первый кадр, выбирается область объекта (ROI) и вычисляются его ключевые точки и дескрипторы SIFT. Если на эталоне слишком мало точек, программа сообщает об ошибке. Также задаются четыре исходных угла эталона и создаётся FLANN-сопоставитель.

### 2.2. Поиск объекта на каждом кадре

Функция `locate()` выполняет следующие операции:

1. Переводит подготовленный текущий кадр в набор ключевых точек и дескрипторов SIFT.
2. Находит два ближайших соответствия для каждого дескриптора эталона с помощью FLANN.
3. Оставляет надёжные пары по ratio-тесту Лоу.
4. При достаточном числе пар оценивает гомографию методом RANSAC.
5. Проверяет количество инлаеров и преобразует углы эталона в координаты текущего кадра.
6. Вызывает `is_plausible()` для проверки полученной рамки.

Если какая-либо проверка не пройдена, функция возвращает `None` вместо рамки.

### 2.3. Визуализация и сохранение результатов

Функция `draw()` отображает зелёный четырёхугольник с подписью вида `Object (N inl)`, где `N` - число инлаеров. При неудачном поиске выводится `NOT FOUND`. В `main()` кадры записываются в выходное видео через `cv2.VideoWriter`; при указании `--csv` сохраняется покадровая статистика.

**Основные параметры алгоритма:**

| Параметр | Значение по умолчанию | Назначение |
|---|---:|---|
| `--nfeatures` | 3000 | Максимальное число ключевых точек SIFT |
| `--ratio` | 0.75 | Порог ratio-теста Лоу |
| `--min-matches` | 15 | Минимальное число хороших соответствий |
| `--min-inliers` | 12 | Минимальное число инлаеров RANSAC |
| `--ransac-thresh` | 5.0 | Порог ошибки перепроекции в пикселях |

### 2.4. Запуск

Установка зависимостей из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r lab2/requirements.txt
```

Пример обработки первого тестового видео из корня проекта:

```bash
python lab2/tracker.py lab2/videos/mona-lisa.avi \
    --output lab2/results/mona-lisa.mp4 \
    --csv lab2/results/mona-lisa.csv \
    --show
```

Если на первом кадре объект занимает не всю площадь изображения, необходимо указать `--select-roi` и выбрать его мышью либо передать координаты через `--roi x,y,w,h`. Нажатие `q` в режиме `--show` досрочно останавливает обработку.

**Столбцы CSV:** `frame` - номер кадра; `found` - факт обнаружения (1/0); `good_matches` - количество хороших соответствий; `inliers` - количество инлаеров; `ms` - время обработки кадра в миллисекундах. Время измеряется для преобразования кадра в оттенки серого и поиска объекта; запись видео, отрисовка и вывод окна в это измерение не входят.

## 3. Результаты работы и тестирования системы

Алгоритм протестирован на **четырёх предоставленных видео** (`mona-lisa.avi`, `mona-lisa-blur.avi`, `mona-lisa-blur-extra-credit.avi`, `simple_track.avi`) и **одном самостоятельно записанном видео** (`my_video.MOV`). Получены следующие результаты:

| Видео | Размер эталона | Точки SIFT эталона | Кадров | Обнаружено кадров | Среднее число инлаеров* | Среднее время, мс/кадр | Скорость, FPS** |
|---|---:|---:|---:|---:|---:|---:|---:|
| Mona Lisa | 640×360 | 343 | 558 | 216 (38,7%) | 49,7 | 37,6 | 26,6 |
| Mona Lisa Blur | 640×360 | 343 | 558 | 193 (34,6%) | 43,4 | 35,2 | 28,4 |
| Mona Lisa Blur Extra Credit | 640×360 | 337 | 558 | 190 (34,1%) | 41,8 | 33,4 | 29,9 |
| Simple Track | 640×360 | 438 | 557 | 138 (24,8%) | 40,5 | 39,8 | 25,1 |
| Собственное видео | 464×824 | 681 | 421 | 216 (51,3%) | 76,0 | 46,0 | 21,8 |

\* Среднее число инлаеров рассчитано **только для кадров, на которых объект был обнаружен**.  
\** FPS получен как величина, обратная среднему измеренному времени обработки; это не полная скорость чтения, отрисовки и записи видео.

**Анализ количественных результатов.** Для исходного видео Mona Lisa доля обнаружений составила 38,7%. Для двух размытых вариантов она уменьшилась до 34,6% и 34,1%; среднее число инлаеров также снизилось с 49,7 до 43,4 и 41,8. Минимальная доля обнаружений получена на Simple Track - 24,8%. На собственном видео достигнут наибольший показатель - 51,3% кадров и 76,0 инлаеров в среднем для обнаруженных кадров. Среднее измеренное время обработки варьировалось от 33,4 до 46,0 мс на кадр.

Эти показатели описывают **частоту срабатывания заданных программных проверок**, а не точность положения рамки. В частности, без покадровой ручной разметки нельзя приравнивать долю обнаруженных кадров к accuracy или делать вывод о числе ложных обнаружений. Качество совмещения рамки с реальными границами объекта требуется оценивать визуально по сохранённым видео.

## 4. Выводы по работе

В ходе лабораторной работы реализован алгоритм поиска и локализации плоского объекта на видео на основе ключевых точек SIFT. Сопоставление дескрипторов выполняется через FLANN, сомнительные соответствия отфильтровываются ratio-тестом Лоу, а пространственное положение объекта определяется посредством гомографии, оценённой методом RANSAC. Полученная рамка представляет собой четырёхугольник и позволяет учитывать перспективу, а не только смещение объекта по горизонтали и вертикали.

Программа была запущена на четырёх тестовых и одном собственном видео. Количественные результаты показали уменьшение доли обнаружений и среднего числа инлаеров для размытых вариантов Mona Lisa по сравнению с исходным роликом. На собственном видео получена наибольшая доля обнаружений среди проведённых запусков. Вместе с тем доля обнаружений оставалась ниже 52% во всех тестах, что указывает на необходимость дальнейшего анализа сложных кадров и, при необходимости, настройки порогов алгоритма.

Основные ограничения метода связаны с недостатком устойчивых текстурных признаков, размытием, перекрытием объекта и возможными ошибками геометрической оценки. В качестве дальнейшего развития можно рассмотреть подбор порогов, дополнительные геометрические проверки и временное сглаживание положения рамки между кадрами.
